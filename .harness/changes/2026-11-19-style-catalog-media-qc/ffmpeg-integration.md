# FFmpeg 在短剧工作台的取舍

生成质量要从画面信息与声音能否传达到观众来判断。编码分辨率相同的竖屏视频，有效画面可以一个铺满屏幕、另一个只有中间一条；音轨存在，也可能各集电平相差很大。补这两项读数能直接服务创作者的选片与交付决策。上游评估版本为 [kajisho5/ffmpeg-skill 的 b8fbd1c](https://github.com/kajisho5/ffmpeg-skill/tree/b8fbd1ce844883ecf678be2386ce1ad92692de1d)。

| 能力 | 用户入口、数据所有者与接入步骤 | 失败处理和验收 |
|---|---|---|
| 首选：逐镜检测有效画幅 | 在现有 `TakeReviewDialog` 为正在看的候选增设按需检查。沿 `routes/workbenchTakes.js` 传分镜 ID、候选 ID，由 `workbenchTakeService.take/localFile` 核实归属并定位该版本的本地片。Node 子进程经 `utils/ffmpegPath.getFfmpegPath` 运行固定参数的多时间窗 cropdetect。返回原始尺寸、旋转信息、每窗有效矩形、时间点和可复查的帧。借鉴上游 cropdetect.py 的取样与投票思路。 | 覆盖全幅竖屏、稳定顶底或左右黑边、夜景、淡入、刻意遮幅、旋转和缺片。各窗证据足够且一致才提示，暗场与遮幅由作者回看。未知结果保持人工审片；采用版本、审片意见及原媒体仍各自由既有服务写入。 |
| 其次：成片最终混音测量 | 在完成导出的记录上提供检查。以 `videoMergeService.renderMerge` 完成后持久化的最终文件为输入，包含 `mergedEpisodePostProcess` 的字幕/BGM/对白及最后一次编码。后台读取 loudnorm JSON，显示综合 LUFS 与真峰值 dBTP、导出版本和检测时间。借鉴 loudness.py 的测量与 check.py 的分项呈现。 | 覆盖已知电平差、静音、无音轨、极短片及重复检测。遇到非有限值或无音轨显示具体原因。仅在项目给出明确目标时标偏差；集间响度可比较，对白可懂度仍需回听。 |
| 后续按需评估：双遍归一 | 当作者明确选择响度目标时才考虑生成新的交付件，保存两遍参数并在编码完成后重新测量。 | 核对原件保留、测量值、时长与音画同步。须另行确认产品范围。 |

黑边和响度建议作为只读结果独立缓存，键包含候选或导出身份、文件指纹和分析参数。macOS 与 Windows 复用项目已有二进制定位，逐滤镜探测可用性。路径、滤镜、音轨或源文件缺失时返回“未能测量”及原因，允许手工复核。现有 `videoMergeService.inspectDeliveryClip` 继续负责正式导出的可解码、时长、音轨等硬条件。并行质量链 AC13 拥有字幕、混音、接缝拼图及每秒抽帧，AC14 拥有尾帧提取和衔接约束。新增测量结果不写入这两条链的任务状态。

**原型实测。** 本机随附的 FFmpeg 对两段同为 288×512 的样片分别测得 288×160（上下各 176 像素黑边）及 288×512。两段相同的合成音轨均得到 −21.80 LUFS、−16.08 dBTP。这个实验能验证检测手段，对真实暗场的误报率和 Windows 滤镜覆盖仍需在实施时取证。

## 分支实现与验证（2026-11-19）

制作页的「选择采用版与审片 → 检测有效画幅」检查选中的本地候选。五个时间窗分别采样，按播放方向呈现有效矩形，点击时间点可以在候选播放器定位。有三个以上可判读时间窗且边缘一致时才提示全幅或稳定暗边，画幅变化、暗场和缺片都有单独反馈。

制作页的「合成视频 → 成片响度」列出本集实际编码完成的导出版本，草稿有单独标识。勾选「包含本剧其他集」可同时查看多个版本的实测值。返回的 LUFS 与 dBTP 来自最终文件默认音轨，包括该版本已经编码的混音。无音轨、静音、短于 0.4 秒以及低于测量门限分别显示。两个检查均按需触发，仅读取媒体。版本与文件指纹共同标识缓存；同一版本发生替换后重新测量。

真实 HTTP 和 FFmpeg 回归覆盖稳定遮幅、旋转、无边、暗场、画幅切换、文件损坏和替换、跨镜候选、已交付双镜合成、已知电平差，以及旧版以首段替代成片的记录。浏览器实测覆盖按时间点回看、切换候选、查看本集成片读数和跨集比较。对上一轮黏土、皮影、复古港片和古典棚拍四条真实试拍各取五个时间窗，均测为 768 × 768 全幅。

双遍响度归一仍是作者明确指定交付目标后的备选功能。自然度、首发可用率和单个可用镜头的成本需按工作台的同条件实拍与双人盲评流程另行取证。[质量试验流程](../../../docs/quality-study.md)

### 版本验收

- 工作分支通过 192 项后端与 36 项前端测试及生产构建。与并行质量链 `9445e30` 的本地合并演练通过 280 项后端与 38 项前端测试及生产构建。
- macOS Lite 1.2.9（构建 1.2.13）的两个 DMG 均通过磁盘镜像、签名和架构检查。直接用各包内的 Electron、SQLite、FFmpeg、ffprobe 调用诊断接口，同一测试片均测得 96 × 64 有效区、上边距 48、−21.81 LUFS 和 −16.08 dBTP。Intel 包通过 Rosetta 运行。Apple 芯片包随附的旧版 ffprobe 也已通过双镜正式交付与多集回归。
- Windows x64 资源已补齐 ffprobe.exe，两种 Windows 打包配置均收录此目录。校验了上游归档摘要及其中 ffmpeg 与仓库版本的逐字节一致性。Windows 原生安装与运行仍待验证。[工具来源](../../../backend-node/tools/ffmpeg/README.md)
