# 本地成对试拍与盲评

在仓库根目录运行下列命令。登记人需要 Node.js 18 或更高版本，制作盲评包还需要项目已有的 FFmpeg 和 ffprobe。工具只读写本地登记文件、媒体与评审表。以下步骤使用作者自己的视频和真实账目。

## 试拍前登记

```sh
node tools/quality-study.cjs init study.json
```

填写 `study.json` 中待测的 `method`、统一费用币种 `currency` 及两位不同评审的姓名或代号。每个 `pairs` 项代表同一作品、集、场景、段的两条制作路径。复制空白配对登记多部作品，给每项填写唯一的 `id`。作品名、集号、场景和段号均使用字符串。

在 `controls` 记录两边共用的剧本版本、参考图编号或内容哈希、模型与版本、画幅、目标时长和可控随机种子。无参考图写空数组，模型没有种子控制可留 `null`。题材、画风或锁定对白等额外控制可加在 `controls` 中。在 `dimensions` 选择本段可观察的维度。例如无对白停顿可以去掉“对白时机”，由有对白的配对验证这一项。可在 `brief` 写两位评审共同需要知道的角色、画风和动作目标，仅填写与分组无关的内容。保持两组条件一致，一次比较一种变化。

```sh
node tools/quality-study.cjs register study.json
```

该命令在首次提交前创建 `study.json.plan.json`。保留副本与试拍清单，后续修改作品、分组、条件和评审人需要开新一轮登记。

## 记录两组实际尝试

旧流程填在 `baseline`，待测流程填在 `method`。每次视频提交按发生顺序追加到所在组的 `attempts`，使用 `outcome` 记录 `usable`（当次产出可用）、`rejected`（产出被弃用）或 `failed`（提交失败）。最终保留的尝试要填 `file`，可用相对清单的路径。媒体只读。每组还要填写以下项目。

| 字段 | 填法 |
|---|---|
| `final` | 最终采用的尝试序号，从 1 开始。全部弃用写 `"discarded"`，尚未结束保留 `null`。 |
| `costs.image`、`costs.review`、`costs.video` | 分别累计该段所有生图、审阅、视频尝试的实际费用，含失败与弃用；免费填 0，未知保留 `null`。 |
| `repairMinutes` | 两位评审打分前，作者为该段返修实际花费的分钟；无需返修填 0。 |

例如一段首次视频提交失败、第二次得到可用视频，登记字段形状为 `"attempts": [{"outcome":"failed"},{"outcome":"usable","file":"clips/本段最终版.mp4"}], "final": 2`。此例仅说明格式。

## 制作和发放盲评包

```sh
node tools/quality-study.cjs blind study.json blind-round-1
```

终端列出已配对数量与缺片段号。对齐完成的每段会生成两个独立评审目录，媒体文件只标“样本编号”和“1/2”。每位评审的播放顺序独立随机。工具保留主视频和第一条音轨，清除文件标签和章节信息。登记人发放前检查画面内的水印、片头及声音是否泄露方案。评审使用支持 MKV 的播放器。

分别只将 `reviewer-1/`、`reviewer-2/` 交给对应评审，根目录的 `private-key.json` 由登记人保管。两人独立观看同编号的两个样片并填写各自的 `ballot.json`。在总评 `overall` 和适用维度的 `vote` 填字符串 `"1"`、`"2"` 或 `"tie"`，分别表示偏好对应样片或持平。每项观察还要填两片均覆盖的 `timeMs`（毫秒整数）和描述具体画面或声音的 `note`。收回时将各自的表放回原来的评审目录。

## 查看结果

```sh
node tools/quality-study.cjs report study.json blind-round-1 > quality-report.json
```

未拍摄时也可运行 `node tools/quality-study.cjs report study.json` 查看缺项。成对条件、媒体或账目变更后要重新制包并收集对应评审；保留旧包供复核。

报告逐作品、逐集、逐场景列出两组的首发可用段数、已试拍段数、最终可用段数、全部提交数、生图/审阅/视频费用与人工返修分钟。首发可用率分母为已实际提交过的段数，每个可用段的平均提交数用全部提交数除以最终可用段数。未完成的段仍计已发生提交，报告显示完成数；分母为零或账目缺项的指标显示 `null`。

每段保留两人逐维判定、具体时间码和意见。媒体缺失、样片重复、关键维度缺测、评审缺席或分歧、画面或成本指标退化时，总状态为“待测”。至少两部独立作品重复获得一致优势并满足完整性条件后，报告才显示“已具备人工决策记录”。作者结合实际样本量和业务可接受的成本判断是否扩大使用。

## 功能验证

```sh
node --test backend-node/test/workbenchQualityStudy.test.js
```

该测试在临时目录生成纯色片和机器构造的表单，核对成功、缺片、分歧、退化、样片变更及费用统计。真实作品的画质、成本优势和人工盲评结论仍待实拍。

## 接缝精剪的三项真人试点

本轮的本地材料在 `backend-node/data/studies/episode-edit-vEwoF7/`。`三镜起始工程.zip` 对应《动物森友会》第一集的「冰冷通知、霓虹刺痛、深夜催缴」，`两镜起始工程.zip` 对应《当职场遇到AI》第一集的「三个提示音、旁听领导开会」。每个包可单独导入，顺剪 MP4 可先做有声播放检查。研究节选沿用原始镜序、已有分镜时长和源片声音。原集的其他镜头不在节选中。保护点表已摘录原分镜的动作、对白与反应，须由作者对实片补准毫秒。其余观察栏留给真人填写，席位号用于排班。两份“工程试剪候选”分别在前镜源片 15 秒、9 秒处切换，供作者检查素材和音画；此时尚无作者采用记录。作品只在本地供主持人准备，发放前由作者确认可向哪些真人展示。

### AC6 · 观感

1. 确认 `AC6登记草案.json` 内登记的三部独立作品，再填写两位已同意的评审代号。每部选一段能观察到切换的连续镜头，三部合计覆盖动作、对白、反应和跨场。作者在 `AC6保护点与缺陷.csv` 预填每段的源镜号、原始时间码、必须保留的台词或故意停顿和完整镜序。冻结两组共用的素材哈希、混音开关、画幅、帧率、简报与规则。复制到新批次，按上文 `register` 登记后从同一起始包分别导出顺剪、经作者试听并采用的精剪。准备阶段的顺剪可用于核对。保留修订和产物，记录本轮真实尝试。
2. 用 `blind` 生成各人独立的两份有声表和播放目录。每人独立完成每部的总偏好、时间码和理由。以“表演”栏记录反应镜头与停顿，以“对白时机”栏记录可懂度和尾音；对任一片观察到的截断、停顿误删或缺镜，在保护点表的独立副本用盲号与片内毫秒记录。各人提交后才揭盲，同作者核对保护点。
3. 每位评审分开按作品计票。三部中各有至少两部偏好精剪，持平不计胜；作品数增加时仍须严格过半。出现关键对白截断、刻意停顿误删或缺镜即不通过，有缺片、缺评或保护点未核清则待测。已有 `report` 可解码逐人投票；此项使用上述三部作品门槛。

### AC10 · 首次使用者

主持人逐人确认从未使用此制作页并征得本地观察同意。每人起始时单独导入同一份三镜工程，关闭模型与建议，固定同一设备和时间上限（本轮拟用 20 分钟，开始前锁定）。给参与者的任务卡为：

> 从已选好的镜头做出一份可播放的正式成片。找到第一镜与第二镜的切换位置，试一处不同的剪法，分别听原版和试剪。决定并采用这处试剪，再把这里恢复到起初的剪法。觉得完成或想停下时请告诉我。

主持人不演示按钮，参与者首次看到任务卡时启动计时。按 `AC10观察表.csv` 填写每步的累计秒数、求助次数、实际帮助、产物或修订号。独立完成要求无操作指导，能播放首次正式成片、两版确有播放、采用后修订变化、恢复后该接缝回到初始剪法。保留超时、退出和失败步骤，五人中至少四人全套独立完成才通过。若改版复测，另招首次使用者。

### AC11 · 建议开关

本轮两份「开关试验工程.zip」已经登记机器辅助核实的审片标记并经导出、重新导入核对。三镜工程前镜 14.800 秒处可见人物把耳机放到颈部、双手落下；两镜工程前镜自 9.247 秒至片尾 9.417 秒测得低于 −40 dB 的声音，9.250 秒处的建议请作者判断是否保留反应。两组各自使用同一工程，观察表已填入包哈希。

同源制作页试点地址为 `/film/<项目ID>?seamPilot=1`。主持人打开「审接缝」，按排班设置「显示剪点建议」。试点复用候选审片意见。作者先有声观看并选出值得对听的接缝，在前镜候选的「审片」窗口取播放器时间，输入 `剪点建议[源片完整SHA256]：具体理由`，记录为待处理。可在本机用 `shasum -a 256 源片.mp4` 取得哈希，或从 `GET /api/v1/episodes/<集ID>/edit` 的对应镜读取 `digest`。请记录实际观察到的动作或声音，例如指出重复发生的位置，并给出必须保留的停顿。工程导出时携带这条候选意见，两组使用同一份带意见的包。系统只显示当前采用候选、相同文件内容且时间位于有效区间的未解决剪点意见。参与者需对听并决定是否采用。没有可提示位置的任务不能测量建议效果，应在计时前更换材料或记为无暴露。

- 用 `AC11交叉观察表.csv` 的四个作者席位，每人做两部不同作品，各做一次开和关。每部作品在两个次序和两种条件各出现一次。每场重新导入同作品的相同起始包，核对哈希与初始修订；同一设备、编辑能力、保护点、任务文本和可用时间。固定每场 20 分钟，在招募前锁定。本轮任务卡为“在给定镜序中改善切换，保留指定对白与停顿，交付一份完整有声成片”。
- 从任务开始到确认提交累计修改时间，单列系统等待秒并扣除。每次作者放弃或修正一项已采用的剪法记一次返工。由未获知条件的复核者按预登记保护点逐个核对，记录误剪时间码和依据。同一缺陷计一次。记录未完成、是否实际显示建议和成片身份，避免只统计顺利场次。
- 同一作品内分别算开与关的修改秒中位数、每人误剪及返工的均值。关键对白和刻意停顿误剪须为零；严格多数作品修改时间下降，且逐作品误剪和返工均未增加才符合开放条件。出现未完成、无暴露、缺记录或条件失衡时先报告缺口。样本少时同时保留逐人原始值。
