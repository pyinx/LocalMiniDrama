# LocalMiniDrama 全流程短剧工作台建设与移植方案

2026-11-18 · 研发方案 · 宿主基线 `16a32d4`（1.2.9）

**工作台的交付单位是一部剧。** 创作者可以从创意、小说、定稿剧本或已有工程起步，在同一项目里完成分集、备图、拆镜、视频、声音、审片和交付。制作到一半关掉应用，回来能知道哪一集可交付、哪一段欠什么；改掉一句台词或一套造型，能看清影响范围，并保住其余已经满意的成果。

工作台的质量目标有两个：**提高第一次就能剪进成片的比例，让最终观感经得起连续观看。** 单段看起来漂亮，仍可能在整集中出现人物忽然换衣、听者抢说台词、连续三镜反复表演同一个动作。方案同时在镜头、分集、跨集三个层面判断质量。历史视频提供回归证据；首轮产品验收使用多部独立作品。

## 1. 创作者怎样走完全程

| 环节 | 创作者的操作与可见产物 | 系统应当保证什么 |
|---|---|---|
| 建项与接续 | 从创意生成大纲与分集；从小说选择改编范围；导入定稿剧本直接备图；从工程包恢复既有分镜和媒体。已有图片、分镜或片段可在对应环节补入。 | 记录原文、作者锁定的事实/台词、目标画幅和项目风格。长文在按章分批前预览覆盖范围，截断或未处理的章节可见。已提供的合格素材可直接采用。 |
| 编剧与分集 | 看全剧主线、人物关系、各集目标与前后衔接，逐场编辑剧本；能随时重读原文或比较改编建议。 | 区分原文事实、改编建议、已采用剧本。写作指导检查每场戏的目标、行动、转折和可拍性。保留沉默、留白和有意重复；成熟剧本的台词改动由作者采用。 |
| 美术与资产 | 建立角色、造型、地点及其状态、关键道具和群像；对比现有图与候选图。一次选定的资产可跨集使用。 | 身份有稳定 ID，同角色换装、同地换光各有明确版本。区分设定卡、空间参考和正式首帧。参考图真的传入生成请求；软件能指出本场缺的是哪张图。 |
| 分镜与预演 | 从剧本拆段，查看镜头目的、人物位置与视线、动作起止、台词、时长和切点。可手改、看单幅关键帧或交换机位。 | 一条分镜记录是一段可生成的视频，段内可含多个镜头。新分镜使用在途的结构化分镜 `segment_ir`；拍摄意图与图像节点、模型提示词各有明确归属。简单段可以跳过预演。 |
| 生成与选片 | 查看真实提交参数，可做单段、按集批量或继续中断的制作；并排比较同段候选，显式采用。 | 后端按实际模型能力编译时长、画幅、参考、首尾帧及声音策略。失败指出镜号与原因；已有候选可播放。新候选成功不会覆盖作者已采用的版本。 |
| 声音与后期 | 根据作品选择原生人声、角色配音、旁白或无对白；调整字幕、字卡、音效和 BGM，通过真实时间轴试听。 | 对齐采用片实际时长。区分说话人、听者和画外音，避免原生对白叠上另一遍 TTS。无声段允许安静；用户要求的音轨或字幕处理失败有可见状态。 |
| 审片与返工 | 从整集预览或接缝图跳到某个生成记录的时间码，指出画风、动作、连戏或声音问题。可换用已有候选，也可仅重做受影响的段。 | 错在台词就回剧本，错在首帧就回首帧。审阅建议与用户已确认内容分开保留。修改后列出需要复核的引用与接缝，未涉及的集和镜头继续可用。 |
| 交付与归档 | 输出每集成片与可迁移工程，查看全剧的逐集完成情况。重新打开工程后能继续制作。 | 完整交付核对所有应交段、采用版本、顺序、音轨和文件可读性。缺片可做带说明的预览，整集交付会列出缺镜。新发布成功才替换上一份可交付成片。 |

**工作台界面围绕三个问题组织。** 项目页显示全剧和每一集的进度、缺项、待复核内容。分集工作区用于剧本、素材、镜头顺序和成片试听。镜头详情集中展示绑定、生成预览、候选、采用与审片记录。沿用现有 FilmCreate、DramaCanvas 和媒体库；画布、列表、批量操作和助手调用相同的后端契约。进度从阶段产物和任务结果计算，只有用户选择、修订与未完成工作需要持久保存。[项目列表](../../frontweb/src/views/FilmList.vue) · [分集工作区](../../frontweb/src/views/FilmCreate.vue) · [画布工作流](../../frontweb/src/composables/useCanvasWorkflowRunner.js)

## 2. 怎样让质量方法适配不同作品

| 长期通用的方法 | 应随作品变化的部分 | 怎样减少返工 |
|---|---|---|
| 让动作具备可见的诱因与结果，每镜承担明确的信息或情绪；对白能按预定节奏读完。 | 家庭戏可以靠沉默和距离推进；喜剧可以靠停顿与误会；悬疑可以靠观众先于人物看到的细节。片头钩子、剪切频率与表演强度可以有不同答案。 | 系统先指出“这个镜头缺什么依据”，给出最小改法。文字或节奏有问题时先改剧本或分镜，避免带着问题出图出片。 |
| 先固定身份与空间关系，再决定每场戏的变化。图像、分镜、视频共用已选画风与资产。 | 写实项目看肤色、材质与光向；二维动画看线条、色块和轮廓；定格或非人角色看形体比例、移动方式与触地感。用户可使用自定义风格。 | 角色基础图可跨集复用，换装只派生造型，换时段只派生场景状态。图文冲突时让作者选择沿用素材还是改视觉设定。 |
| 区分场景资料图、动作开始的首帧、动作结束的尾帧及普通参考。 | 对话关注视线和说话顺序；群像关注主次与走位；连续动作关注空间和运动方向；蒙太奇允许主动断开衔接。 | 在便宜的文本和静态图阶段检查绑错图、越轴、重复动作或无依据的运镜。模型不支持的控制项在预览时报出。 |
| 作者、分镜撰写者、审阅者和渲染器有清晰职责。 | 普通镜头可直接生成；高风险表演、跨段连续动作、跨集造型变化或作者指定的段才增加一次审阅。 | 先做确定性校验，再用带上下文的创作判断。审阅返回“集/段/镜、依据、问题、最小修法”。文本模型只评价提供的文本；实际图像/视频由能读取媒体的模型或人工评。 |

**技能接入。** 为“场内目标与对白”“资产与图文一致性”“调度与表演”“审片与返修”分别编写小份原创方法，记录适用阶段、输入、产物、版本及正反例。方法按镜头任务组合；题材影响叙事，画风影响视觉，供应商只影响可执行参数。常规生成按钮在对应服务中读取这些方法，聊天助手引用同一份资源。既有 Mastra 助手可协助选方法、解释或提出局部修改，付费生成仍由原业务服务处理。无法使用审阅模型时保留人工检查和已有编辑入口。[已有技能加载入口](../../backend-node/src/mastra/index.mjs) · [既有画风解析](../../backend-node/src/utils/dramaStyleMerge.js) · [帧提示服务](../../backend-node/src/services/framePromptService.js)

## 4. 与在途质量链共用哪些契约

下表按 2026-11-18 核对的规格快照（AC1–AC40，文件 SHA-256 前缀 `965a1fbde47f`）划分。依赖达到验收并合入后再正式接线。接口或任务编号有变化时，以该能力实际合入的契约为准。[在途规格及验收项](../../.harness/changes/2026-11-18-jimeng-quality-chain/spec.md)

| 现有或在途能力的维护方 | 工作台补齐的职责 |
|---|---|
| 原有项目、分集、剧本、小说导入和画风配置；在途 T18 负责剧本生成规则和体检。 | 多入口接续、长文来源覆盖、全剧人物关系和跨集事实提示。扩展原剧本生成/体检输出，沿用用户已确认文本。 |
| 在途 T1–T9 负责模型能力、分段、IR、投影、编译、单段/整集检查及预览。T4 要求有 IR 的分镜经 IR 接口编辑，旧字段由其投影。 | 将导演方法用于编译前的创作；图像提示读取对应镜头。UI、批量及助手对同一段走同一服务。已有整集规则直接展示，生成后审片关联真实媒体。 |
| 在途 T10–T12 负责角色造型、群像、场景状态/反打、道具状态和级联软删。 | 跨集名单、按作用域复用素材、区分人工锁定与待补项。重提取先看差异，避免先删再建导致旧镜失去绑定。 |
| 在途 T13/T14 负责字幕、BGM、逐句 TTS、抽帧/接缝图和条件尾帧；T15 负责工程包内 IR 与变体往返、ID 重映射。 | 建立分镜采用版本、审片意见、局部重做及完整交付。所有媒体消费者读同一采用结果；新增采用关系在原包格式上扩展，复用 T15 的映射。 |
| 在途 T16/T17 负责可选即梦后端、报价确认、同次操作防重与恢复查询；T19 负责该变更收尾。 | 批量和普通供应商沿原视频服务记录任务与结果。对不提供报价、查询或幂等标识的供应商如实展示能力；工作台不代用户切换计费渠道。 |

新补入规格的七项直接影响工作台。即梦按整集报价和确认（AC34），通用模型走既有编译族（AC35），换模型拆段调用既有重规划接口并消费其变更清单（AC36）。台词对稿、画风句派生和每集每场的连续性表直接复用（AC37–39）；跨集复核仅追加对前后集已确认事实和采用素材的比较，具体站位与轴线仍由该集该场持有。实际提交文本按模型配置即时编译（AC40），工作台记录生成当时的请求快照，编辑时回到分镜 IR。

视图读取项目、分集、资产、IR、生成记录和已采用结果。为支持新行为，建议只增加**已有实体表达不了的事实**：本次采用哪个生成记录、哪个输入修订产生了候选、哪个时间码需要复核、尚未执行的批次项。立项时逐项核对实际落地的 schema；每项只设一个写入入口，优先扩展现有实体。[现有数据迁移](../../backend-node/src/db/migrate.js) · [任务服务](../../backend-node/src/services/taskService.js) · [项目导入](../../backend-node/src/services/dramaImportService.js)

**可提前开展的工作。** 先给现有小说导入补覆盖用例：章节摘要会截取过长输入，摘要失败会回退到章首节选；整章内容是否真正参与改编，需要显式标记。并行准备两部多集验收工程、生成后审片的时间码记录和采用/交付测试。等 T4/T8/T9 接线完成后接入创作与分镜编辑，等 T13/T15 完成后验证成片与工程往返。这样同一组逻辑有单一维护方，开发可分头推进。[小说导入](../../backend-node/src/services/novelImportService.js) · [剧本生成](../../backend-node/src/services/storyGenerationService.js)

## 5. 稳定性的验收放在实际制作路径上

| 真实制作中的事件 | 系统行为与可执行检查 |
|---|---|
| 点两次生成；断线时厂商可能已经接单 | 同一主动操作用稳定标识在 SQLite 事务中认领任务，相同输入重试返回原任务，主动重拍另立操作。有厂商标识只查原任务；没有可恢复依据时显示“结果待核实”，避免自动再次扣费。用本地假供应商统计实际出站次数。[视频创建入口](../../backend-node/src/routes/videos.js) · [恢复轮询](../../backend-node/src/services/videoService.js) |
| 批量生成途中关页、重启或取消 | 现有画布在前端逐段执行，启动时还会处置遗留异步任务。批次在后端保存分镜顺序、执行步骤与对应任务 ID；重开后先对账，展示已完成、在查、待核实和未开始项。取消阻止后续派发，已提交项如厂商无法取消则保留可查。已完成段不会重算。[画布批次](../../frontweb/src/composables/useCanvasWorkflowRunner.js) · [任务状态](../../backend-node/src/services/taskService.js) |
| 改台词、换造型、改模型或迟到回调 | 根据依赖列出受影响的镜头、配音、相邻接缝和成片。改字幕排版只触发后期；换已采用角色图只提示引用该版本的段；换模型重做能力校验。已有片保留可回看。迟来的旧候选可入历史，不能覆盖新采用。 |
| 列表选了 A，批量连帧、合成或 ZIP 却读 B | 分镜持有采用的生成记录 ID，素材文件由生成记录持有。检查该候选成功且属于本镜；两个窗口冲突时返回最新修订。详情、浏览器截帧、服务端取尾帧、最终合成和包导出均用同一解析。旧镜无显式采用时沿旧读法，无法可靠匹配时请作者选片。[合成取片](../../backend-node/src/services/dramaService.js) · [项目导出](../../backend-node/src/services/dramaExportService.js) |
| 少镜、坏片、资源过期或合成过程中换了配音 | 正式交付按次冻结应交分镜、有序采用记录、字幕/语音与混音输入。先查引用，再解码全部采用片；按真实片长验证顺序、画幅、时长和需要的轨道。失败指出具体镜号和原因，保留上次成片。旧预览与新交付在界面上有不同状态。[合成实现](../../backend-node/src/services/videoMergeService.js) · [音画后处理](../../backend-node/src/services/mergedEpisodePostProcess.js) |
| 换机器或升级旧项目 | 用旧库、旧包、新旧分镜混合工程跑“导出 → 导入到 ID 不同的新库 → 改一段 → 再交付”。核对各集人物归属、同名不同场景、造型及道具状态、采用片哈希；本地绝对路径和云账户绑定有明确替换/重绑提示。新功能按项目启用，已有媒体和作者改动保留；回退先停止新派发，使用能读新引用的兼容版或已验证备份。 |

**质量与成本怎样判定。** 用同一作品、同台词与选图、同一模型版本和时长目标做成对比较，一次只改变待测方法；评剧本改编时单独固定故事事实。逐作品、逐场景列出首发可用段数/全部试拍段数，并用全部视频提交数除以最终可用段数衡量重抽，含失败与最终弃用的段。同步记录生图、审阅、视频成本和人工返修时间。两名评审隐藏方案标签，用时间码说明表演、视线、动作衔接、身份、画风和对白时机的优劣。样本不足或评审分歧的场景维持可选；在独立作品上反复受益、关键维度无退化的方法才进入默认流程。首版不承诺未经实拍验证的提升比例。
