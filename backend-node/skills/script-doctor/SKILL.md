# 剧本深审与对白活人感精修

这个 Skill 只做两件事：**有证据地诊断**和**最小改动地提议**。不整篇重写，不替作者决定爽点和风格。

## 何时使用

- 用户说「帮我看看这集哪里不行」「台词像说明书」「前三集够不够抓人」时。
- 现有 8 维剧本体检给了分数，但用户想知道「问题在哪一行、往哪个方向改」时。
- 用户给了明确的诊断方向，要你只动被点名的几处时。

## 工具调用步骤

### 第一阶段：诊断

1. 先用 `get_current_project` 读取当前剧与当前集，确认剧集归属和剧本原文。
2. 根据用户需求选 `mode`：
   - `selection`：题材与赛道判断，只看定位是否清楚。
   - `first-three`：前三集生死线，看开场危机、集尾钩子、升级节奏。
   - `dialogue`：对白活人感，查说明书腔、排比金句、缺潜台词。
   - `full`：综合深审（默认）。
3. 调用 `review_episode_deep`。它产出带 `id`、`severity`、`location`、`what`、`why`、`direction` 的 findings，并写入 notes。
4. 向用户逐条报告 finding。**必须带位置（`location`）和原因（`why`）**，不能只说「台词不好」。
5. 每条 finding 后面问一句「要不要针对这条给改法」。用户没点名的，不进入第二阶段。

### 第二阶段：提议

6. 用户确认要改的 finding id 后，调用 `propose_script_edits`，只传这些 id。
7. 工具返回逐处 `{path, before, after}` 提议。向用户展示每处**改前 → 改后**，并说明对应哪条 finding。
8. 用户说「应用」「保存」后，才用 `save_episode_script` 把改后的完整剧本写回。**不要自行应用提议。**
9. 用户说「放弃」或只认可其中几处时，按用户的选择手动组装完整剧本再保存；不要保存整份提议。

## 证据格式

一条合格的 finding：

- `id`：`f1`、`f2`……稳定短标识，第二阶段靠它定位。
- `severity`：`blocking`（不改不能拍）、`warn`（影响质量）、`info`（可选优化）。
- `location`：剧本里的具体位置，如「第二场第三句」「集尾最后一句」。
- `what`：问题是什么，引用原文片段。
- `why`：为什么是问题，对应哪条创作纪律。
- `direction`：一句话修改方向，不写替换文本。

一条合格的改动提议：

- `finding_id`：必须属于用户确认过的 finding。
- `path`：原文里可定位的句子或字段。
- `before`：必须与原文逐字一致。
- `after`：改后文本，只改被点名的问题。

## 失败处理

- `not_found`：剧或集不存在，让用户先打开正确的剧。
- `empty_script`：剧本为空，让用户先写或导入剧本。
- `invalid_mode`：工具参数错误，改用四个合法 mode 之一。
- `review_invalid`：模型输出不符合约定格式，诊断/提议整份作废。向用户说明失败，不展示半截结果。
- `review_failed`：模型调用异常。提示用户稍后重试，不改变剧本。
- `invalid_selection`：finding id 不存在或没选，重新展示可用 finding 让用户选。
- `invalid_path`：提议里的原文在剧本中找不到，整份拒绝；向用户说明证据对不上，重新诊断。
- `conflict`：笔记被别处更新，重新诊断；不要拿旧 finding 去生成提议。

## 作者确认门槛

- 诊断阶段不改任何剧本。
- 提议阶段只写 notes，不改 `episodes.script_content`。
- 只有用户明确确认后才用 `save_episode_script` 保存完整剧本。
- 用户没点名的 finding 不提议；用户点名的 finding 里，只改被诊断命中的字段，不动台词原意、关键对白、场景顺序和秒数。

## 能力边界

- 不整篇重写剧本，不替用户决定爽点、风格、合规判断。
- 不修改既有 8 维体检的打分逻辑；这个 Skill 是它的上游补充，不是替代。
- 不生成分镜、不改视频、不调用出图接口。
- 详细的对白规则见 `references/dialogue-rules.md`；各 mode 的诊断重点见 `references/deep-review-rubric.md`。
