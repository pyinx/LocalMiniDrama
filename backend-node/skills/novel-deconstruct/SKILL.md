# 小说与长素材先拆后改

先把素材拆成可核对的事实，再谈改编。不要一上来就逐段改写，那样容易把小说的心理描写带进剧本，变成流水账。

## 何时使用

- 用户说「我有一本小说要改成短剧」「这段怎么分集」时。
- 用户已经导入过小说（剧集里有 `novel_source`），想重新规划分集时。
- 用户问「原著里哪些事实不能丢」时。

## 工具调用步骤

1. `get_source_facts` 读取当前剧的小说源。返回 `not_found` 说明这部剧还没有导入小说，引导用户先用现有的小说导入功能。
2. 记下返回的 `source_hash`。它代表当前源文本；后续所有提议都带上它。
3. 和用户一起把事实卡补进笔记：人物身份、关系、不可变事实、事件线、动机链、改编取舍。字段说明见 `references/source-fields.md`。
4. `propose_episode_split` 传入 `source_hash` 和想要的集数，得到按可拍事件切分的提议。
5. 把提议展示给用户，说明每集覆盖哪些事件。用户确认后，用现有的导入/分集工具落地；这个 Skill 自己不写剧集。

## 证据与失败处理

- `source_changed`：源文本已经变了（用户重新导入或手动改过）。重新调用 `get_source_facts` 取新 hash，旧的事实卡和切分提议不再可信，向用户说明。
- `invalid_count`：集数不在 1–200 之间，改用合法值。
- `not_found`：当前剧没有小说源，或剧不存在。
- 每次返回都要带 `source_hash`，让用户知道这份建议对应哪一版原文。

## 作者确认门槛

- 事实卡只由用户口述或确认后写入；模型推断的内容标注「待确认」。
- 分集切分只是提议，不写 episodes；用户说「就这么分」后才用现有工具落地。
- 不要续写原文后文，不要下载或抓取外部小说。

## 能力边界

- 没有写剧本文本的工具，没有替换章节识别与导入接口的工具。
- 不修改已有分集正文与分镜。
- 源文本的身份完全依赖 `source_hash`；文本一变就必须重做事实核对。
