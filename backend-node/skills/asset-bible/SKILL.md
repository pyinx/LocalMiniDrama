# 跨集资产盘点与状态锁

信物碎裂、伤口、手机亮屏这些东西跨集最容易穿帮。先把全剧资产列清楚，再按每集剧本提议状态变化。

## 何时使用

- 用户说「这封信是不是每集都在」「道具状态对不对」「哪些图还没好」时。
- 写分镜之前，想确认引用的角色/场景参考图是否齐全。
- 用户想按剧本补一批道具状态时。

## 工具调用步骤

1. `get_asset_matrix` 读取当前剧的资产矩阵和已有提议。矩阵每次重新读 DB，包含角色是否有参考图、场景是否有参考图、现有道具与连续性锁。
2. 若用户要看状态变化，调用 `propose_prop_states`。它按当前集剧本提议道具状态（碎裂、点亮、沾血、被拿走等），写入笔记。
3. 展示提议，逐条说明「哪个道具、什么状态、剧本里的依据」。明确告诉用户：这只是提议，还没有创建资产。
4. 用户确认后，用现有的资产变体接口创建道具状态；这个 Skill 自己不创建。
5. 分镜前用 `check_asset_lock` 检查某条分镜引用的资产是否就绪。返回 `asset_unready` 时列出缺参考图的角色/场景，让用户先补图。

## 证据与失败处理

- `no_props`：这部剧还没有道具，先让用户建立道具。
- `empty_script`：当前集没有剧本，先写或导入剧本。
- `proposal_invalid`：模型输出不合约定或道具 id 不存在，整份提议作废；向用户说明失败，不展示半截结果。
- `asset_unready`：有角色或场景缺参考图。列出具体缺哪些，不自动调用出图（那是付费接口）。
- `not_found`：剧/集/分镜不存在。

## 作者确认门槛

- `propose_prop_states` 只写笔记，不写 `prop_states` 表，不调用 `assetVariantService.create`。
- 不调用付费出图接口；补图由用户用现有功能决定。
- 不绕过变体的作者确认流程。
- 不修改角色头身拼接规则；头只生成一次、身体按造型生成的约束保持不变。

## 能力边界

- 矩阵是笔记里的只读快照，每次调用工具都会重读 DB；不要缓存旧结果当事实。
- 不改变连续性锁；锁由现有跨集复核流程管理。
- 不新建资产表；道具状态仍用现有 `prop_states`。
